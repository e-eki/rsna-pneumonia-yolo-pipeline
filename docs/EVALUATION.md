# Оценка модели

Что считает `evaluate.py`, какие бывают метрики и как их интерпретировать.

## 🚀 Запуск

```bash
# Последняя обученная модель
python -m src.evaluate --config configs/config.yaml

# Конкретная модель
python -m src.evaluate --config configs/config.yaml \
    --model runs/train/<run_name>/weights/best.pt
```

Результаты сохраняются в runs/val/<run_name>/ — имя автоматически выводится из train-папки.

## 📊 Метрики

# mAP@0.5 — основная
Mean Average Precision при IoU = 0.5. Показывает, насколько хорошо модель находит очаги. Основная метрика для сравнения с другими решениями RSNA.

# mAP@0.5:0.95
Усреднённая по порогам IoU от 0.5 до 0.95 с шагом 0.05. Более строгая — требует точного совпадения границ боксов. Для RSNA с размытыми границами очагов обычно в 2–3 раза ниже, чем mAP@0.5.

# Precision и Recall
- Precision — доля правильных предсказаний среди всех сделанных. «Из тех, что модель назвала очагами, сколько действительно очаги».
- Recall — доля найденных очагов среди всех реальных. «Из всех настоящих очагов сколько модель нашла».

Для медицинской детекции recall важнее precision: пропустить пневмонию хуже, чем показать лишний раз. Эту границу можно сдвинуть через порог conf при инференсе.

# AR@0.50 (Average Recall)
Сколько очагов модель находит, если дать ей право на 100 предсказаний на изображение. Верхняя граница возможностей модели.

AR@0.50 = 0.92 означает: модель видит 92% очагов. Она просто пока плохо их ранжирует — не всегда самые уверенные предсказания попадают в топ. Это резерв для улучшения через калибровку.

## Разделение порогов: map vs infer
Ключевой момент: пороги для подсчёта mAP и пороги для инференса — разные вещи.

- Для mAP (evaluation.map)
map:
  conf: 0.001   # почти не отсеиваем — нужна полная PR-кривая
  iou:  0.6     # стандарт COCO для NMS

Модель отдаёт все предсказания, включая низкоуверенные. mAP строится по отсортированному по confidence списку — если отсеять всё ниже 0.25, останется 1–2 предсказания и mAP будет почти нулевым.
Значения совпадают с дефолтами YOLO при обучении — так evaluate.py даёт результат, сопоставимый с последней эпохой train.

- Для инференса (evaluation.infer)
infer:
  conf: 0.25   # показываем только уверенные предсказания
  iou:  0.45   # NMS схлопывает пересекающиеся боксы

Используется в predict.py / демо. Обычные пороги YOLO.

Если перепутать: evaluate.py с conf=0.25 покажет mAP близкий к нулю (проверено на практике). Симптом — precision = 1.0 при recall ≈ 0.

## 📁 Что сохраняется при оценке

runs/val/<run_name>/
├── predictions.json           # предсказания в COCO-формате
├── confusion_matrix.png       # матрица ошибок
├── confusion_matrix_normalized.png
├── PR_curve.png               # Precision-Recall кривая
├── F1_curve.png               # F1 в зависимости от conf
├── P_curve.png, R_curve.png
├── val_batch0_pred.jpg, ...   # предсказания на картинках
└── val_batch0_labels.jpg, ... # ground truth на тех же картинках

Файлы val_batch*_pred.jpg vs val_batch*_labels.jpg — самый удобный способ визуально сравнить, что модель предсказала и что было размечено.

## 📉 Как читать confusion matrix
В confusion_matrix.png:

- Левый верхний угол — True Positives (модель нашла очаг там, где он есть);
- Правый верхний — False Positives (модель «увидела» очаг на здоровом снимке);
- Левый нижний — False Negatives (модель пропустила очаг);
- Правый нижний — True Negatives (модель правильно не нашла очаг на здоровом снимке).

Для медицинских задач FN критичнее FP: пропустить пневмонию опаснее, чем назначить дополнительное обследование. Если FN высокий — снижаем conf при инференсе (жертвуем precision ради recall).
