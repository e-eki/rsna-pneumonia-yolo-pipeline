## 🎯 Технические решения

Не «что есть в проекте» (это в [README](../README.md)), а **почему сделано именно так** — те решения, которые требуют объяснения.

### Промежуточные данные сохраняются на диск

После каждой стадии результат пишется в `data/` (raw → processed → samples). Альтернатива — держать всё в памяти и передавать объекты между скриптами — плохо работает в Colab: сессия может отвалиться в любой момент, и результаты предыдущих шагов потеряются. Диск даёт точку возобновления.

### Абсолютные пути для артефактов YOLO

YOLO получает `project` как `Path(...).resolve()`, а не относительный путь. Причина — известный баг Ultralytics: при относительном пути он добавляет свой `runs/detect/` к уже существующей структуре, и результаты попадают в `runs/detect/runs/train/`. Абсолютный путь отключает эту логику.

### Парные папки `runs/train/` и `runs/val/`

Для каждого обучения создаётся `runs/train/<run_name>/`, для оценки — `runs/val/<run_name>/` с **тем же именем**. Имя val-папки автоматически выводится из пути к весам:

```text
runs/train/2026-10-02_yolov8s_30ep/weights/best.pt
              ↓
runs/val/2026-10-02_yolov8s_30ep/
```

Это даёт сортировку по алфавиту, при которой пары «обучение ↔ оценка» всегда лежат рядом — легко сравнивать.
